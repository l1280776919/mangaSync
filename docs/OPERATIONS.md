# 日常运行、备份与升级

## 收藏与同步

收藏页读取 SQLite 快照，翻页和本地筛选不再重复拉取整个远端收藏。快照超过 5 分钟时后台刷新；失败后至少等待 1 分钟再自动尝试。主动刷新可以立即重试。同账号并发刷新合并为一个请求。部分失败合并已获取条目，保留旧数据并显示错误；仅完整成功的刷新可以删除已不在远端的收藏。

账号页“立即同步”为增量同步；“更多”提供继续上次同步、只重试失败项、完整核验。任务页同时显示下载和同步结果。每本漫画的待处理、成功、失败状态保存在数据库，服务重启会继续 pending 项目。已经创建的下载任务仍由下载队列独立恢复。首次获取收藏清单失败时，应使用“立即同步”重新刷新；逐本重试不能恢复尚未获取的收藏页。

对本地完整漫画，章节数量提示与文件名、大小、修改时间指纹均相同，且最近一次完整检查在 6 小时以内时，可跳过回源。缺少章节数量提示、指纹变化、超过 6 小时或选择完整核验都会回源。缓存存在更新发现延迟，需要立即确认时选择完整核验。文件内容在大小和时间均被人为保持的情况下不在指纹保证范围内。

## 下载续传与完整性

哔咔图片清单任一分页解析失败、图片地址缺失或总数不一致都会报错。未完成章节保存到隐藏的 `.章节名.resume` 目录，重试复用已校验图片。图片清单变化后失效旧的续传页；完整章节通过目录交换提交，提交失败保留原目录。禁漫原有单页续传增加图片解码和 SHA-256 校验，并随清单变化失效旧页。图片校验收据不是恶意文件篡改防护机制。

未完成文件占用磁盘空间；不要在任务运行时手动清理续传目录。磁盘保护仍会暂停新下载。回收站与备份也会占用容量。

## 凭据保护

首次启动此版本会生成数据目录中的 `secrets.key`（32 字节、0600），将站点密码和令牌迁移为 AES-GCM 密文。之后密码更新和登录令牌均加密写入。已有加密数据却缺少密钥时拒绝启动，不会生成新密钥覆盖。数据库迁移开启 secure_delete 并清理 WAL；此前导出的明文数据库备份不受迁移影响。

密钥必须单独备份，并与数据库备份分开保管。控制了运行账户或同时获得数据库和密钥的人仍然可以解密凭据。该机制保护静态数据库副本，不替代主机权限和 HTTPS。

## 备份与恢复

以下命令操作数据目录中的数据库和配置，不包含漫画文件。漫画目录需另行备份。备份目标和恢复目标必须是不存在的新目录。

```sh
./mangasync -data /srv/mangasync -backup-to /backup/mangasync-20261006
./mangasync -verify-backup /backup/mangasync-20261006 -key /secure/secrets.key
./mangasync -restore-backup /backup/mangasync-20261006 -key /secure/secrets.key -restore-to /srv/mangasync-restored
```

在线备份使用 SQLite `VACUUM INTO`，包含已提交的 WAL 数据；清单记录 SHA-256、版本和密钥指纹。密钥不放入备份目录。请另行保存原始 secrets.key。校验覆盖文件哈希、SQLite quick_check 和凭据解密。恢复使旧浏览器会话失效，重新登录后使用；不会覆盖运行数据，也不会自动切换服务。旧版未加密数据库的备份可不传密钥，恢复后首次正常启动会加密。

## 升级与回滚

```sh
sudo scripts/deploy.sh dist/mangasync /usr/local/bin/mangasync mangasync http://127.0.0.1:8787/api/health /srv/mangasync
```

必须显式提供数据目录。脚本停止服务后用新程序生成一致性备份，再替换二进制并做健康检查。健康检查失败时恢复数据库、配置、密钥及旧二进制，保留失败时的数据供排查。漫画和缓存目录保持原位。第一次启用凭据加密后，不能仅回滚旧二进制而继续使用加密后的数据库。

本机升级回滚副本与密钥位于相邻的受限路径，目的是故障回滚；异机备份时应把密钥放到不同的受控位置。部署期间不要启动第二个服务实例操作同一数据目录。

## 验证

- `npm --prefix web test`：组件、请求竞态与同步轮询。
- `go test -race ./...` 和 `go vet ./...`：完整性、快照、检查点、备份恢复和并发。
- `npm --prefix web run test:e2e`：Chromium 中运行登录、搜索、下载入队、阅读、同步和网络错误恢复。站点响应采用受控模拟，不代表真实上游可用性。CI 自动安装 Chromium 后执行。
- 可用 `MANGASYNC_CHROMIUM=/path/to/chromium` 指定已有 Chromium，仅用于测试。
- 设置页网络诊断显示本进程各主机的请求数、HTTP/网络失败和响应头耗时，不记录请求正文、密码、令牌或漫画标题。HTTP 200 的业务响应错误需结合同步错误类别判断。


## 下载调度与校验

两个站独立限制后台请求并发，同站的所有下载任务共用并发池；每站上限取图片线程设置与 16 的较小值。阅读请求不进入下载池，仍使用阅读侧的限制，不保证带宽配额。修改设置后新任务使用新池，已有任务继续使用旧池。图片解码与编码全局最多同时处理两张，避免大量任务同时解码撑满 NAS 内存。

图片连接超时 15 秒、响应头超时 30 秒、单次 HTTP 请求上限 120 秒，单图重试预算 3 分钟（禁漫包括域名切换）。重试最多三次并采用可取消退避；遵守 `Retry-After`，过长的限流等待直接报错交由用户稍后重试。取消任务会中止网络和退避等待；已开始的图片解码/编码完成后才释放处理槽。

哔咔修复已落盘章节时，在页面清单一致的条件下校验并复用完好页面，只请求缺失或损坏页面。下载速度只统计新请求的有效图片字节，不把复用页面算入速度。禁漫复用解码结果并在写入时生成校验值，减少重复解码与文件回读。

下载结束复用本轮已验证的详情、页数，仍检查本地页序和缺页；整本下载发现缺章会失败，只下载指定章节则仅对请求范围判定任务成功，书库的整本完整状态单独记录。远端在本轮快照之后新增的章节由后续同步发现。
